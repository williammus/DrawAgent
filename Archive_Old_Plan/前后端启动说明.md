## 2. 当前项目启动流程分析

### 2.1 后端启动流程

后端入口不是直接手敲 `uvicorn`，而是先经过 `backend/manage.py`。

执行：

```powershell
python backend/manage.py dev
```

实际流程：

1. `backend/manage.py` 读取环境变量 `APP_HOST` 和 `APP_PORT`。
2. `manage.py dev` 调用：

```powershell
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

3. `backend/app/main.py` 中的 `create_app()` 创建 FastAPI 应用并注册：
   - CORS
   - RequestContextMiddleware
   - 错误处理
   - `health/session/chat/upload/artifacts/generation` 路由
4. FastAPI `lifespan` 启动时会初始化：
   - `SessionStore`
   - `TempFileManager`
   - Prompt Registry / Renderer
   - Agent Runtime
   - LangGraph Workflow Runner
   - Image Adapter
   - Session / Chat / Generation Service
   - 周期性清理任务
5. 联调时前端最先依赖的后端接口是：
   - `POST /api/session/init`
   - `GET /healthz`
   - 后续聊天与 SSE 再进入：
     - `POST /api/chat/message`
     - `GET /api/chat/stream/{session_id}`
     - `POST /api/upload`
     - `GET /api/artifacts/{session_id}`
     - `POST /api/generate/{session_id}`

### 2.2 后端配置加载方式

`backend/app/core/settings.py` 使用 `pydantic-settings` 从 `.env` 读取配置。

默认关键配置如下：

- `APP_HOST=127.0.0.1`
- `APP_PORT=8000`
- `FRONTEND_ORIGIN=http://127.0.0.1:5173`
- `IMAGE_PROVIDER=mock`

说明：

- 当前仓库中 `backend/.env` 已存在。
- 模板文件为 `backend/.env.example`。
- 如果要做真实模型和真实出图联调，需要补充：
  - `LLM_API_KEY`
  - `LLM_BASE_URL`
  - `LLM_MODEL`
  - `IMAGE_API_KEY`
  - `IMAGE_BASE_URL`
  - `IMAGE_PROVIDER`

### 2.3 前端启动流程

前端入口是 Vite 开发服务器。

执行：

```powershell
npm.cmd --prefix frontend run dev
```

实际流程：

1. `frontend/package.json` 中 `dev` 脚本实际执行 `vite`。
2. `frontend/vite.config.ts` 固定开发地址：
   - `host: 127.0.0.1`
   - `port: 5173`
3. `frontend/src/main.tsx` 挂载 React 根组件。
4. `frontend/src/App.tsx` 启动后立即执行：
   - `useSessionBootstrap()`
   - `useSSEStream()`
   - `useChatWorkflow()`
5. `useSessionBootstrap()` 会在页面初次加载后自动请求：

```text
POST /api/session/init
```

因此前端不是“打开页面再手动建会话”，而是页面初始化时自动向后端要一个 session。

### 2.4 前端访问后端方式

前端没有配置 Vite 代理，而是直接调用完整后端地址。

来源：

- `frontend/.env.example`
- `frontend/src/lib/constants.ts`

默认值：

```env
VITE_API_BASE_URL=http://127.0.0.1:8000
```

说明：

- 当前仓库中 `frontend/.env` 不存在也能运行，因为代码内置了默认地址。
- 为了 phase7 联调稳定，建议仍然补一个 `frontend/.env`，避免不同机器默认值漂移。

建议内容：

```env
VITE_API_BASE_URL=http://127.0.0.1:8000
VITE_APP_TITLE=DrawAgent 2.0
```

## 3. 推荐启动顺序

联调时按下面顺序启动：

1. 先启动后端
2. 确认 `GET /healthz` 正常
3. 再启动前端
4. 打开 `http://127.0.0.1:5173`
5. 观察页面初始化是否成功自动创建 session

原因：

- 前端首屏就会请求 `POST /api/session/init`
- 如果后端未就绪，前端会直接进入初始化失败态

### 5.2 当前环境下的注意事项

1. `python backend/manage.py dev` 使用的是 `uvicorn --reload`。
2. 在当前 Codex Windows 沙箱里，`--reload` 会触发 `watchfiles`/多进程相关权限问题，出现 `WinError 5`。
3. 因此在当前环境里，联调更稳的后端启动方式是直接使用不带热重载的 `uvicorn`。

当前机器可用的后端替代命令：

```powershell
D:\ProgramData\Anaconda3\envs\DrawAgent\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

说明：

- 这条命令等价于正常启动后端服务，但不启用热重载。
- 如果在你自己的终端环境里没有沙箱限制，优先仍使用 `python backend/manage.py dev`。

## 8. 常用排查点

### 8.1 前端页面打开后直接报初始化失败

优先检查：

1. 后端是否已启动
2. `http://127.0.0.1:8000/healthz` 是否可访问
3. `frontend/.env` 中 `VITE_API_BASE_URL` 是否写错
4. 后端 `.env` 中 `FRONTEND_ORIGIN` 是否仍为 `http://127.0.0.1:5173`

### 8.2 后端能启动但 `manage.py dev` 报权限/重载问题

处理方式：

1. 当前环境下改用不带 `--reload` 的 `uvicorn`
2. 或在本机正常终端中运行 `python backend/manage.py dev`

### 8.3 前端 `vite` 报 `spawn EPERM`

这通常不是项目代码问题，而是当前执行环境对 `esbuild` 子进程启动有限制。优先在本机终端直接运行：

```powershell
npm.cmd --prefix frontend run dev
```
